# PRD: Recipe Sharing Platform

## 1. Product Overview

A web app where users can create an account, upload recipes, browse recipes from other users, save favourites, and discover cooking inspiration through search, filters, categories, and tags.

The MVP should focus on making recipe publishing and browsing smooth, clean, and useful. No need to boil the ocean yet — just make the core loop excellent.

---

## 2. Target Users

Primary users:

* Home cooks who want to save and share recipes
* Food creators/bloggers who want a simple recipe profile
* People looking for cooking inspiration
* Families wanting a central recipe library

---

## 3. Core User Stories

As a user, I want to:

* Sign up and log in
* Create a profile
* Upload a recipe with ingredients, steps, images, cooking time, servings, and tags
* Browse public recipes
* Search recipes by keyword
* Filter recipes by category, cuisine, difficulty, dietary tags, and cooking time
* View a full recipe page
* Save recipes to my favourites
* Edit or delete my own recipes
* View another user’s recipe profile

As an admin, I want to:

* View all recipes
* Remove inappropriate content
* Manage categories/tags
* Feature selected recipes

# 7. Suggested Database Schema

## `profiles`

```sql
id uuid primary key references auth.users(id) on delete cascade,
username text unique not null,
display_name text,
bio text,
avatar_url text,
created_at timestamp with time zone default now()
```

## `recipes`

```sql
id uuid primary key default gen_random_uuid(),
user_id uuid references profiles(id) on delete cascade,
title text not null,
slug text unique not null,
description text,
hero_image_url text,
prep_time_minutes int,
cook_time_minutes int,
servings int,
difficulty text,
cuisine text,
meal_type text,
notes text,
is_public boolean default true,
created_at timestamp with time zone default now(),
updated_at timestamp with time zone default now()
```

## `ingredients`

```sql
id uuid primary key default gen_random_uuid(),
recipe_id uuid references recipes(id) on delete cascade,
position int not null,
quantity text,
unit text,
name text not null,
notes text
```

## `recipe_steps`

```sql
id uuid primary key default gen_random_uuid(),
recipe_id uuid references recipes(id) on delete cascade,
position int not null,
instruction text not null
```

## `tags`

```sql
id uuid primary key default gen_random_uuid(),
name text unique not null,
slug text unique not null
```

## `recipe_tags`

```sql
recipe_id uuid references recipes(id) on delete cascade,
tag_id uuid references tags(id) on delete cascade,
primary key (recipe_id, tag_id)
```

## `favourites`

```sql
user_id uuid references profiles(id) on delete cascade,
recipe_id uuid references recipes(id) on delete cascade,
created_at timestamp with time zone default now(),
primary key (user_id, recipe_id)
```

# 9. Step-by-Step Implementation Guide

## Phase 1: Project Setup

1. Create the Next.js app:

```bash
npx create-next-app@latest recipe-platform
```

Use:

* TypeScript
* Tailwind CSS
* App Router
* ESLint

2. Install Supabase packages:

```bash
npm install @supabase/supabase-js @supabase/ssr
```

3. Create a Supabase project.

4. Add environment variables:

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
```

---

## Phase 2: Supabase Setup

1. Create database tables.
2. Enable Row Level Security.
3. Add policies so:

   * Anyone can read public recipes.
   * Users can create recipes only as themselves.
   * Users can update/delete only their own recipes.
   * Users can favourite recipes only as themselves.
4. Create storage buckets:

   * `recipe-images`
   * `avatars`

---

## Phase 3: Authentication

Build:

* Signup page
* Login page
* Logout action
* Auth callback handling
* Protected dashboard route

Start with email/password. Add Google login later if needed.

---

## Phase 4: Profiles

Build:

* Auto-create profile after signup
* Profile settings page
* Username validation
* Avatar upload
* Public profile page

---

## Phase 5: Recipe Creation

Build the recipe form with:

* Basic recipe details
* Dynamic ingredients list
* Dynamic method steps
* Image upload
* Tags
* Public/private toggle

Use Zod validation so bad data doesn’t sneak in wearing a trench coat.

---

## Phase 6: Recipe Browsing

Build:

* `/recipes`
* Recipe card grid
* Search by title/description
* Filters by cuisine, meal type, difficulty, tags
* Sort by newest

---

## Phase 7: Recipe Detail Page

Build:

* Full recipe page
* Ingredients list
* Step-by-step method
* Save/favourite button
* Owner-only edit/delete controls

---

## Phase 8: Favourites

Build:

* Save/unsave recipe
* Favourites page
* Prevent duplicate favourites

---

## Phase 9: Admin/Moderation

For MVP, keep this simple:

* Add `role` field to profiles
* Admin-only route
* Admin can hide/delete recipes

---

## Phase 10: Deployment

1. Push project to GitHub.
2. Deploy to Vercel.
3. Add Supabase environment variables to Vercel.
4. Test auth redirect URLs.
5. Test image uploads.
6. Test database permissions.

---

# 10. MVP Build Order

I’d build in this order:

1. Supabase schema
2. Auth
3. Profiles
4. Recipe create/edit/delete
5. Public recipe browsing
6. Recipe detail page
7. Favourites
8. Search and filters
9. Image upload
10. Admin moderation

That gives you the core loop quickly:

**Sign up → upload recipe → browse recipe → save recipe.**

That’s the product. Everything else is seasoning.

SQL for database table

profiles table
reate table if not exists public.profiles (
  id uuid primary key references auth.users(id),
  username text unique not null,
  full_name text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

alter table public.profiles enable row level security;

-- Anyone can view profiles (needed for /users/[username])
drop policy if exists "profiles are public read" on public.profiles;
create policy "profiles are public read"
on public.profiles
for select
to public
using (true);
-- Users can insert only their own profile row (usually created by trigger, but safe)
drop policy if exists "users can insert their own profile" on public.profiles;
create policy "users can insert their own profile"
on public.profiles
for insert
to authenticated
with check (id = auth.uid());
-- Users can update only their own profile
drop policy if exists "users can update their own profile" on public.profiles;
create policy "users can update their own profile"
on public.profiles
for update
to authenticated
using (true)
with check (id = auth.uid());


recipes table
---------
create table if not exists public.recipes (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users(id) not null,
  title text not null,
  description text,
  cook_time_minutes int check (cook_time_minutes is null or cook_time_minutes >= 0),
  difficulty text check (difficulty is null or difficulty in ('easy', 'medium', 'hard')),
  ingredients text[] not null,
  category text not null,
  instructions text[] not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

alter table public.recipes enable row level security;

create policy "Recipes are viewable by everyone"
on public.recipes
for select
to public
using (
  true
);

create policy "Users can insert their own recipes"
on public.recipes
for insert
to authenticated
with check (user_id = auth.uid());

create policy "Users can update own recipes"
on public.recipes
for update
to authenticated
using (user_id = auth.uid());

create policy "Users can delete own recipes"
on public.recipes
for delete
to authenticated
using (user_id = auth.uid());




-- =========
-- recipe_likes
-- =========
create table if not exists public.recipe_likes (
  id uuid primary key default gen_random_uuid(),
  recipe_id uuid not null references public.recipes(id) on delete cascade,
  user_id uuid not null references public.profiles(id) on delete cascade,
  created_at timestamptz not null default now(),
  constraint recipe_likes_one_per_user unique (recipe_id, user_id)
);

-- =========
-- recipe_comments
-- =========
create table if not exists public.recipe_comments (
  id uuid primary key default gen_random_uuid(),
  recipe_id uuid not null references public.recipes(id) on delete cascade,
  user_id uuid not null references public.profiles(id) on delete cascade,
  body text not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  deleted_at timestamptz null,
  constraint recipe_comments_body_len
    check (char_length(trim(body)) between 1 and 5000)
);


-- =========
-- RLS for likes and comments tables
-- =========

-- Anyone can read likes (for counts, UI, etc.)
drop policy if exists "recipe_likes_select_all" on public.recipe_likes;

on public.recipe_likes
for select
to public
using (true);

-- Only signed-in users can like, only as themselves

on public.recipe_likes
for insert
to authenticated
with check (user_id = auth.uid());

-- Only signed-in users can unlike (delete) their own like

on public.recipe_likes
for delete
to authenticated
